# RobotDeploymentAssistant 舞台编导：简化需求微任务包

本包按你最新确认的 5 项需求重新收缩，取代之前范围过大的 43 份任务包。

## 最终交付范围

1. **2D 轨迹**：单机器人绘制/编辑轨迹；多机器人群体轨迹。
2. **阵型设计**：定义机器人相对位置和朝向，编辑后应用到机器人组，并能沿群体路径保持队形。
3. **拖拽编排**：将真实舞蹈/动作素材和轨迹拖到单机/多机时间轴轨道。
4. **3D 整体预演**：用同一播放时钟驱动多台机器人模型，支持播放/暂停/跳转/停止。
5. **本地地图管理**：手动导入 PCD、列表、删除、加载到 2D 舞台。

远程遥控建图和实时地图上传依赖机器人端，目前只做只读扩展边界说明；不创建假按钮、不模拟上传。

## 关键技术边界

- 本轮“播放”是 **3D 虚拟预演**，不是把时间轴编排下发到真机。
- 机载舞蹈别名不等于本地 3D 动作关键帧。若动作文件没有姿态数据，预演必须显示“该动作暂不可做真实姿态预览”，不可编造动作。
- 当前 LoRa 是单向链路，不伪造 ACK/READY/在线状态。
- 不修改原主页及入口，不修改 `app.py`、`main.py`、`web/**`、`backend/**`、installer、构建脚本和核心配置。
- 复用现有 `StageCanvas2D`、`StageViewport3D`、PCD loader、样条、阵型、FK、时间轴和存储实现；修改前按当前源码再次核实。

## 每个微任务的完成标准

1. 实际 Qt 操作进入真实业务代码。
2. 有真实数据源和业务状态变化。
3. 有持久化的功能必须重开验证。
4. 有正常路径和失败/边界测试。
5. UI 无重复按钮、无新旧样式混搭、无遮挡和错位。
6. `python scripts/stage_director_guard.py verify --root .` 通过。
7. Gemini 汇报文件路径、测试命令、测试结果、人工验收方法和未完成项，然后停止。

## 运行 Prompt 长度检查
在解压目录运行：

```powershell
python scripts/check_prompt_limits.py
```

每份 Prompt 目标不超过 180 行（用户上限 200 行，留有余量）。

## 单任务验证建议

把 `scripts/run_one_task_validation.ps1` 复制到原项目的 `scripts/` 目录（如已有同名文件先比较，不覆盖），然后在原项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_one_task_validation.ps1
```

如果某任务只修改了特定模块，可传入更窄的 `-CompileTargets` 和 `-TestTargets`。不要跳过 guard verify，也不要重新 capture 覆盖原始基线。
