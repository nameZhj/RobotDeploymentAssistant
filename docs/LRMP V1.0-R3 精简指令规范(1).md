# LRMP V1.0-R3 精简指令规范

## 1. 协议设计原则

本协议采用“简洁业务命令 + 内部可靠传输”的设计。

上位机业务接口只负责描述目标机器人和执行操作：

```
TARGET|COMMAND[,PARAM1,PARAM2,...]
```

例如：

```
A|STAND
A|MOVE,0.5,0,0,2
A|PREP,8001,9001
```

上位机通信模块自动生成请求编号、序列号和二进制数据帧，完成认证、发送、超时与重试。

STM32 根据地址和命令编号，将任务交给本地网关功能或机器人 Linux Agent。

### 命令字段词典

| 字段    | 作用                    |
| ------- | ----------------------- |
| TARGET  | 目标机器人别名或网关 ID |
| COMMAND | 操作名称                |
| PARAM   | 命令参数，可按需要省略  |

### 目标TARGET规则

- `A`、`B`、`C`：已注册机器人。
- `GW_xxxx`：尚未绑定逻辑编号的指定网关。
- `ALL`：仅用于设备发现。
- 上位机多选机器人时，由通信模块生成对应的多条定向消息。

### 响应规则

用户发送命令时，不需要手动填写 REQ 或 REQUEST_ID。

传输模块内部保留：

- REQ：业务请求。
- RSP：处理结果。
- EVT：异步事件。
- ACK：帧接收确认。
- SEQ：会话序列号。
- REQUEST_ID：请求关联编号。
- SRC_ID / DST_ID：实际发送者和接收者。
- CRC / HMAC：完整性与认证校验。

响应日志必须显示消息来源设备，不得仅显示接收方 CTRL。

对于短操作，机器人返回最终结果。

对于联网、部署、导航准备等长时间任务，机器人先返回 ACCEPTED，再通过状态事件或 STATUS 查询反馈最终结果。

## 2. 设备管理命令

| 命令       | 参数       | 具体作用           |
| ---------- | ---------- | ------------------ |
| `DISCOVER` | 无         | 搜索设备           |
| `BIND`     | alias      | 绑定逻辑机器人编号 |
| `SETUP`    | job_id     | 完成首次自动初始化 |
| `DEPLOY`   | job_id     | 执行软件更新或部署 |
| `STATUS`   | 可选查询项 | 获取状态           |

### DISCOVER

```
ALL|DISCOVER
```

STM32 返回网关 ID、注册状态和固件版本。

发现请求可以广播，但必须设置随机响应退避。

### BIND

```
GW_8C2F|BIND,A
```

将网关绑定为机器人 A。

执行前必须完成设备认证，首次配对还需要满足物理配对条件。认证过程由上位机通信模块自动完成，不要求操作员手工发送挑战响应指令。

### SETUP

```
A|SETUP,601
```

机器人自动执行：

1. 检查主机通信。
2. 连接预设 Wi-Fi。
3. 读取机器码并验证设备身份。
4. 获取并安装有效 License。
5. 获取部署任务并下载软件。
6. 校验镜像和发布签名。
7. 等待安全维护条件。
8. 完成软件部署和健康检查。

任务失败时保持可查询的失败状态，不能因为自动流程失败而执行未经授权的程序。

### DEPLOY

```
A|DEPLOY,602
```

部署编号为 602 的更新任务。

任务内容由服务器预先创建并签名。不得将 LoRa 指令中的任意字符串直接执行为系统命令。

### STATUS

```
A|STATUS
A|STATUS,NET
A|STATUS,ID
A|STATUS,LICENSE
A|STATUS,DEPLOY
A|STATUS,OWNER
A|STATUS,SHOW
A|STATUS,CLOCK
```

各状态由 Linux Agent 或 STM32 返回。

`STATUS,ID` 返回用于设备关联的机器码摘要，不直接公开全部硬件序列号。

## 3. 直接运动控制命令

| 命令         | 参数                | 具体功能                        |
| ------------ | ------------------- | ------------------------------- |
| `STAND`      | 无                  | 请求 FixStand                   |
| `GAIT`       | 无                  | 请求进入 RL 步态模式            |
| `PASSIVE`    | 无                  | 请求进入被动状态                |
| `FORWARD`    | t                   | 前进 t 秒                       |
| `BACK`       | t                   | 后退 t 秒，具体别名需与源码核实 |
| `MOVE_LEFT`  | t                   | 左移 t 秒                       |
| `MOVE_RIGHT` | t                   | 右移 t 秒                       |
| `TURN_LEFT`  | t                   | 左转 t 秒                       |
| `TURN_RIGHT` | t                   | 右转 t 秒                       |
| `MOVE`       | forward,left,turn,t | 组合运动控制                    |
| `DANCE`      | action_name         | 执行单次舞蹈                    |
| `STOP`       | 无                  | 停止当前运动                    |
| `RELEASE`    | 无                  | 安全释放人工控制权              |

### MOVE

```
A|MOVE,0.5,0,0,2
```

参数依次表示：

- forward：归一化前后控制量。
- left：归一化左右平移控制量。
- turn：归一化旋转控制量。
- t：有效持续时间，单位秒。

三个运动控制量范围均为 `[-1,1]`，由 Agent 负责映射到实际 G1 遥控器或控制策略接口。

时间参数不得超过控制器配置允许的最大持续时间。超时后必须自动清除运动目标。

### DANCE

```
A|DANCE,KUNGFU
```

根据已安装动作资源和 License，执行指定舞蹈动作。

动作资源由 Agent 的动作注册表管理，未安装或未授权的动作必须拒绝执行。

### STOP

```
A|STOP
```

统一停止语义：

- MANUAL：停止当前运动，保留控制权。
- CHOREO：请求安全中断当前编排。
- FREE：返回已处于空闲或安全保持状态。

STOP 是软件停止请求，不能替代机器人物理急停。

### RELEASE

```
A|RELEASE
```

仅用于释放当前控制端持有的 MANUAL 控制权。

Agent 在确认当前运动目标已安全撤销后释放租约。正在执行 CHOREO 时不得通过 RELEASE 强制释放控制权。

### 兼容扩展

原有 `GROUP1`、`GROUP2`、`GROUP3`、`OPENING`、`BUTTON` 和 `MASK` 可继续作为高级兼容指令，由已认证的管理端使用。

这些命令不属于普通用户默认显示的核心控制指令，尤其 `BUTTON` 和 `MASK` 必须进行白名单、控制状态及权限检查。

## 4. 舞蹈编排命令

| 命令          | 参数                         | 功能               |
| ------------- | ---------------------------- | ------------------ |
| `PREP`        | plan_id,run_id               | 准备编排任务       |
| `PLAY`        | run_id,t0_ms                 | 在统一时间启动任务 |
| `BARRIER`     | run_id,barrier_id,release_ms | 同步节点放行       |
| `STOP`        | 无                           | 请求中断当前编排   |
| `STATUS,SHOW` | 可选 run_id                  | 查询编排进度       |

### PREP

```
A|PREP,8001,9001
```

其中：

- plan_id=8001：编排方案编号。
- run_id=9001：本次执行的唯一编号。

Linux Agent 自动完成：

1. 从服务器或已验证的本地缓存读取任务清单。
2. 校验方案签名、任务版本、摘要和目标机器人身份。
3. 检查导航地图、动作资源、机器人授权和系统状态。
4. 为当前编排任务申请 CHOREO 控制权。
5. 根据任务文件执行表演前的初始定位导航。
6. 到达起始位置后返回 READY。

同一 plan_id 的内容必须不可变。修改编排方案时生成新的 plan_id，避免同名任务对应不同内容。

### PLAY

```
A|PLAY,9001,1900000000000
```

含义：

机器人 A 在 UTC 毫秒时刻 `1900000000000` 开始执行 run_id=9001 的编排任务。

允许执行的条件：

- PREP 已成功。
- 本机任务状态为 READY。
- 任务身份及版本验证通过。
- 时钟同步质量满足任务要求。
- 启动时间仍有足够提前量。
- 机器人处于安全可启动状态。

所有参与机器人必须使用一致的启动时刻。

### BARRIER

```
A|BARRIER,9001,2,1900000030000
```

表示：

本次运行编号 9001 的第二个同步屏障，经协调器检查后，允许在给定时间放行。

这条命令仅用于任务文件中明确要求协调器放行的同步节点。

如果屏障条件不成立，不得因为到达计划时间就直接执行后续舞蹈。

### STOP

```
A|STOP
```

当 A 正在执行 CHOREO 时，STOP 等价于安全中断当前编排，不再单独设置 `PLAN_ABORT` 作为用户指令。

### STATUS,SHOW

```
A|STATUS,SHOW
```

可以返回：

```
owner=CHOREO
run_id=9001
state=RUNNING
step=3
```

具体响应通过二进制协议传输，上述格式为上位机调试显示。

## 5. 控制权规则

Linux Agent 内部维护：

| 控制权 | 含义           |
| ------ | -------------- |
| FREE   | 无业务任务占用 |
| MANUAL | 上位机直接控制 |
| CHOREO | 编排任务控制   |

基本原则：

- 合法运动命令在 FREE 时可以自动获取 MANUAL。
- PREP 在 FREE 时可以申请 CHOREO。
- MANUAL 和 CHOREO 互斥。
- STOP 不等于立即释放所有控制权。
- RELEASE 仅处理 MANUAL。
- 编排自然完成后由 Agent 自动进行安全收尾及释放控制权。
- 真实遥控器和底层安全保护具有更高优先级。

ControlArbiter 内部继续使用控制租约及防重放机制，但普通操作员不需要填写 lease_id。

机器人重启、控制会话失效或控制权更换后，之前的控制命令必须失效。

## 6. 多机器人规则

多选机器人由上位机进行目标展开：

```
A|STAND
B|STAND
C|STAND
```

除设备发现外，不使用 ALL 代替当前勾选的机器人集合。

编排任务在创建时固定目标列表，后续新加入的机器人不会自动参与。

多机器人同步执行要求：

1. 所有目标机器人完成 PREP 并返回 READY。
2. 所有机器人完成时钟质量检查。
3. 上位机向全部目标发送相同 T0 的 PLAY。
4. 在 T0 之前检查所有必要响应。
5. 若有机器人无法确认，按安全策略尽力取消整场表演。
6. 不得将 LoRa ACK 当作严格原子同步保证。

对于需要更严格同步和安全协调的场景，应增加可靠的局域网协调机制或专门的同步通信设计。

## 7. 三种典型操作流程

### 新机器人初始化

```
ALL|DISCOVER
GW_8C2F|BIND,A
A|SETUP,601
A|STATUS
```

其中认证、配对、请求确认和错误重试由通信模块自动处理。

### 直接控制 A、B

```
A|STAND
B|STAND

A|GAIT
B|GAIT

A|MOVE,0.5,0,0,2
B|MOVE,0,0,-0.4,2

A|DANCE,KUNGFU

A|STOP
B|STOP

A|RELEASE
B|RELEASE
```

### A、B 多机器人舞蹈编排

```
A|PREP,8001,9001
B|PREP,8001,9001
```

等待两台机器人均返回 READY，并确认时钟同步质量满足要求。

然后设置统一的未来启动时刻：

```
A|PLAY,9001,1900000000000
B|PLAY,9001,1900000000000
```

如果任务文件中还包含动态同步屏障：

```
A|BARRIER,9001,2,1900000030000
B|BARRIER,9001,2,1900000030000
```

任务自然完成后，Robot Agent 自动收尾、保存记录并安全释放 CHOREO 控制权。

如果需要提前终止：

```
A|STOP
B|STOP
```

## 8. 保留但不暴露给普通用户的机制

虽然上位机命令已精简，以下机制仍属于正式通信实现的必要组成部分：

- 源地址、目标地址和设备别名映射。
- 身份认证、首次配对、消息完整性校验。
- 请求编号、SEQ、防重放和幂等处理。
- ACK、响应与异步事件。
- 控制权租约及失联保护。
- 自动部署任务持久化、签名校验和回滚。
- 编排任务身份、资源检查和时间同步。
- 物理遥控器接管及底层安全保护。

这些属于系统的内部可靠性和安全要求，不能因为用户命令简化而删除。

## 9. 尚未实现的能力边界

本协议为设计建议，不能直接视为现有 STM32 和 G1 程序已经支持。

可优先复用的已有控制接口包括：STAND、GAIT、PASSIVE、定时方向运动、DANCE、STOP 及原有按钮映射。

以下功能需要后续新增代码或验证现有能力：

- LRMP 完整通信帧和安全认证。
- STM32 网关绑定与双向状态通信。
- SETUP 自动初始化和镜像部署。
- 通用 MOVE 到现有虚拟遥控器的映射。
- ControlArbiter 控制权管理。
- 机器人定位与导航。
- Timeline Executor 时间线调度。
- PLAY 定时启动和 BARRIER 同步机制。
- 多机器人异常协调。
